The recommendations

1. Fix mobile pinch-zoom (confirmed live today)

The site currently blocks pinch-to-zoom on phones. We'd change it to the standard setting that lets people zoom. 35% of visitors are on mobile (646 of ~1,820 users last month), and blocking zoom is an accessibility (WCAG) failure — a real issue for a public-interest org. ~10 min. Very low risk — one line, instantly reversible.

2. Give Donate a single real URL (confirmed live today)

Today the homepage opens a donate popup via a query-string link, and there's also a /donate/ page — two URLs for the same action. We'd pick one canonical /donate/ page and redirect the rest to it. Analytics shows donate traffic split across both URLs, with the popup version showing 0.8 seconds of engagement. One URL means donations are countable, bookmarkable, and linkable from emails. ~30 min. Medium risk — this is the money path, so it gets a full backup and click-through test. Reversible.

3. Fix the broken volunteer link (from May 22 audit)

The volunteer call-to-action points at a Mailchimp survey URL that only works inside an email; on the website it dead-ends. We'd point it at a real signup page or embedded form. Volunteer signups is a stated goal; this link currently converts no one. ~15 min. Low risk.

4. Remove the dead analytics tag (confirmed live today)

An old Universal Analytics tag still loads on every page. Google stopped processing its data on July 1, 2024 — it collects nothing. We'd remove it; the current analytics (GA4 + Tag Manager) stay untouched. ~10 min. Very low risk — it's already dead.

5. Update the footer copyright (confirmed live — says "© 2020")

Change the footer to the current year, set to update automatically. A 2020 date signals an abandoned site to first-time visitors and funders. ~5 min. Very low risk.

6. Security hygiene (from May 22 audit)

Hide WordPress usernames from public lookup and disable an unused remote-access entry point (XML-RPC). The audit found usernames are publicly exposed. Note: the host's firewall already blocks password-guessing attacks, so this is cleanup, not an emergency — but worth doing. ~30 min. Low risk (we confirm nothing needs XML-RPC first).

7. Measurement setup (needs Google Analytics access — separate from WordPress)

Mark donations and form submissions as "conversions" in Google Analytics, and tag the newsletter/social links so we can see where traffic comes from. Right now GA records zero conversions — it can't tell us if any page drives a donation or signup, though the visit data is fine. The form-submit events are already being collected (14 last month); they just need to be flagged. Blocked on granting Ashton Editor access to Google Analytics — does not require touching WordPress.

8. Growth — repeat what works (content decision, not a quick fix)

The single best-performing page last month was the Colorado BRT comment guide (444 views, 56 seconds average engagement) — an action/comment guide. We'd replicate that format for other campaigns and surface recent articles on the homepage. It's a proven pattern on your own site. This is a content/communications decision for the team.
